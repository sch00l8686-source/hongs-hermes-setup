# Obsidian Vault Query

Obsidian 위키에서 질문에 필요한 페이지와 연결만 선택적으로 읽고, 근거가 되는 `[[페이지]]`를 밝힌 답변을 만든다. 질의의 새 종합은 사용자 승인 없이 위키에 기록하지 않는다.

## When to Use

- 사용자가 Vault/위키에 이미 축적된 지식을 바탕으로 질문할 때.
- 기존 `/쿼리`, `/query` 표현을 포함한 요청.
- 여러 노트의 주장·도구·기법·패턴을 비교하거나 현재 지식 상태를 묻는 요청.
- Do not use for: 새 `raw/` 원본 반영은 `obsidian-vault-ingest`, Vault 구조의 건강 점검은 `obsidian-vault-lint`를 사용한다.

## Prerequisites

1. Vault 절대 경로와 루트 프로젝트 규칙을 확인한다.
2. `wiki/index.md`가 존재하면 반드시 먼저 읽는다. index가 없거나 최신성이 의심되면 그 사실을 답변의 한계로 밝힌다.
3. `AI 기초 개념.md`처럼 사용자 학습용으로 AI 컨텍스트에서 제외하라고 명시된 파일은 읽지 않는다.

## Procedure

1. **질문과 범위를 해석한다.** 대상 도구, 개념, 비교 기준, 원하는 결과물이 모호하여 조사 경로가 달라지면 짧게 확인한다.
   - 완료 기준: 답변해야 할 주장 또는 판단 기준이 명확하다.
2. **index에서 진입점을 찾는다.** `wiki/index.md`와 필요한 검색으로 후보 페이지를 좁힌다.
   - 완료 기준: 질문과 직접 관련된 초기 페이지가 식별됐다.
3. **필요한 페이지만 읽고 링크를 따른다.** 후보 페이지를 읽은 뒤, 질문에 필요한 근거·반론·정의가 있는 링크만 추가로 읽는다. Vault 전체나 무관한 카테고리를 통째로 읽지 않는다.
   - 완료 기준: 결론을 뒷받침하거나 한계를 설명할 최소 근거가 모였다.
4. **근거 상태와 상충을 분리한다.** `sources`, `confidence`, 명시된 상충 내용을 확인한다. 읽은 지식과 사용자가 검증한 지식을 섞지 않는다.
   - 완료 기준: verified/tested/unverified와 상충 여부가 답변에 반영됐다.
5. **답변한다.** 결론, 근거, 한계/상충, 다음 검증을 구분한다. 사용한 Vault 페이지를 실제 Obsidian 형식인 `[[페이지명]]`으로 밝힌다.
   - 완료 기준: 독자가 답의 근거 페이지로 돌아갈 수 있다.
6. **새 종합 여부를 판별한다.** 답변이 Vault에 없던 재사용 가치 있는 비교·종합·직접 검증 패턴이면, 위키에 남길지 사용자에게 묻는다. 승인 전에는 위키를 수정하지 않는다.
   - 완료 기준: 지식 기록 필요성이 있다면 승인 요청으로 끝났다.

## Answer Contract

- Vault에 없는 사실, 최신 외부 정보, 일반 모델 지식을 Vault의 근거인 것처럼 쓰지 않는다.
- 근거가 없으면 불명확하다고 말하고, `confidence: unverified`와 같은 Vault 상태를 존중한다.
- 복수 선택지가 있는 구조·제품 결정에는 대안, 트레이드오프, 추천 이유, 되돌리는 비용을 제시한다.
- 새 소스 조사나 웹 검색이 필요하면 Vault 질의 결과와 외부 근거를 명확히 분리한다.

## Pitfalls

- index만 읽고 결론을 내리지 않는다. 실제 관련 페이지와 source 링크를 확인한다.
- 인바운드 링크가 없다는 이유만으로 페이지의 내용을 무시하지 않는다. lint 문제와 지식의 진위를 혼동하지 않는다.
- 답변이 좋다는 이유만으로 자동으로 위키 페이지·로그 항목을 만들지 않는다.

## Verification

답변 전에 확인한다.

- `wiki/index.md`를 먼저 읽었는가
- 실제로 읽은 페이지를 모두 `[[링크]]`로 밝히는가
- 근거의 confidence와 상충을 과장하지 않았는가
- 위키 쓰기가 있었다면 사용자의 명시 승인이 있었는가
