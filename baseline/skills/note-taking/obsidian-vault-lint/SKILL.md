# Obsidian Vault Lint

Vault의 원본·위키·특수 문서를 읽기 전용으로 대조해 연결, 근거, 최신성, 운영 규칙의 위반 후보를 보고한다. lint는 자동 수정이나 스키마 변경을 수행하지 않는다.

## When to Use

- 사용자가 Vault/위키의 lint, 건강 점검, 고아 노트, 미처리 원본, 링크·frontmatter 점검을 요청할 때.
- 기존 `/lint` 표현을 포함한 요청.
- 인제스트 전에 현재 지식베이스의 정합성이나 유지보수 우선순위를 알고 싶을 때.
- Do not use for: 새 원본 처리에는 `obsidian-vault-ingest`, 특정 질문 답변에는 `obsidian-vault-query`를 사용한다.

## Prerequisites

1. Vault 절대 경로를 확인하고 루트 및 하위 폴더 규칙을 읽는다.
2. `raw/`는 불변이다. lint를 위해서도 수정·이동·삭제·처리 표시를 하지 않는다.
3. `wiki/log.md`가 추가 전용인지, `wiki/index.md`·`overview.md`·`synthesis.md`가 존재하는지 확인한다.

## Procedure

1. **점검 범위를 선언한다.** 기본 범위는 `raw/`와 `wiki/` 및 특수 파일이다. 대형 Vault에서 전체 검사 비용이 지나치면 우선순위를 보고하고 사용자와 범위를 정한다.
   - 완료 기준: 검사할 경로와 제외 경로가 명확하다.
2. **구조와 메타데이터를 검사한다.** `wiki/`의 평면 구조, 일반 페이지의 필수 frontmatter, 파일명·특수 파일 계약, type/tags/confidence의 허용값을 실제 규칙과 대조한다.
   - 완료 기준: 구조·메타데이터 위반 후보가 경로별로 수집됐다.
3. **링크와 참조를 검사한다.** 깨진 `[[링크]]`, 인바운드 링크가 없는 고아 페이지, 여러 곳에서 언급되지만 자체 페이지가 없는 핵심 개념, 빠진 상호 참조를 찾는다.
   - 완료 기준: 링크 문제를 깨짐/고아/보강 후보로 분리했다.
4. **근거와 상태를 검사한다.** source 페이지의 `sources`가 실제 `raw/` 원본을 가리키는지, 원본 파일과 `wiki/index.md` Sources가 대조되는지, 오래된 `confidence: unverified`가 방치됐는지 확인한다.
   - 완료 기준: 미처리 원본과 근거·신뢰도 후보가 분리됐다.
5. **내용 정합성을 검사한다.** 새 근거로 무효화됐을 수 있는 서술, 병기되지 않은 상충, `overview.md`와 `synthesis.md`가 최근 source/핵심 페이지와 어긋나는 후보를 찾는다.
   - 완료 기준: 확정 오류와 사람이 판단해야 할 내용 충돌을 구분했다.
6. **보고만 한다.** 심각도와 근거를 붙여 결과를 제시하고, 자동 수정하지 않는다. 수정안·우선순위·되돌리기 비용을 제안하되 사용자 승인 전 파일을 건드리지 않는다.
   - 완료 기준: 각 항목에 경로, 근거, 권장 조치, 승인 필요 여부가 있다.
7. **스키마 변경 신호를 별도로 판단한다.** type/태그 축/층 구조/필드/파일명/특수 파일 역할을 바꿔야 한다는 제안은 실제 트리거가 있을 때만 낸다: query가 답을 찾지 못함, 동일 lint 위반이 세 번 이상 반복됨, ingest가 규칙 부재로 진행 불가. 트리거가 없다면 관찰만 보고하고 스키마는 변경하지 않는다.
   - 완료 기준: 스키마 제안에는 실제 트리거 또는 보류 이유가 명시됐다.

## Report Format

```text
## 요약
- 검사 범위
- 즉시 수정이 필요한 항목 수 / 검토 필요 항목 수

## 문제
- [심각도] 경로 — 관찰 근거 — 영향 — 권장 조치 — 승인 필요 여부

## 미처리 원본
- [[raw/...]] — index 대조 상태

## 상충·최신성
- 관련 [[페이지]] — 판단이 필요한 이유

## 스키마 상태
- 변경 트리거 충족 여부와 근거

## 다음 제안
- 사용자 승인이 필요한 최소 수정 묶음
```

## Pitfalls

- lint가 발견한 후보를 사실로 단정하지 않는다. 특히 의미상 모순·누락 연결은 사용자 판단 또는 추가 근거가 필요할 수 있다.
- 고아 페이지를 자동 삭제하지 않는다. 아직 연결되지 않은 유효한 지식일 수 있다.
- `raw/`의 파일 목록과 index를 대조할 때 raw 원본 자체에 처리 상태를 기록하지 않는다.
- 규칙 개선 아이디어만으로 스키마를 재설계하지 않는다.

## Verification

최종 보고 전에 확인한다.

- `raw/`와 `wiki/`의 파일을 변경하지 않았는가
- 각 발견 항목에 실제 경로와 관찰 근거가 있는가
- 미처리 원본, 링크/고아, confidence, overview/synthesis 정합성을 모두 검사했는가
- 자동 수정 제안과 실제 실행을 명확히 분리했는가
